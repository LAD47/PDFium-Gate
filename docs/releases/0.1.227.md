# PDFium Gate 0.1.227

0.1.227 is a usability, localization, document-register and Community-release-quality release candidate.

## Highlights

- DocumentInfo now exposes **Edit** in both the top and bottom action areas, with **Cancel** and **Save** available in both places while editing.
- Factory metadata/category defaults follow the selected UI language while stable UUIDs, properties and machine values remain language-independent.
- User-customized metadata labels, category names and option labels remain user-owned and are preserved across language changes.
- Settings is reorganized into compact, collapsible groups.
- The production PDF Document Register is visually and conceptually separated from the synthetic/native Bases learning examples.
- The PDF Document Register is PDF-first, supports persistent per-view column visibility, and includes quick filters for Active, Missing, Errors, Unregistered and All.
- Invalid metadata records expose concrete diagnostics, while register/diagnostic text remains selectable and copyable.
- Multiple records pointing to the same PDF are grouped and compared; duplicate metadata records can be deleted through a guarded identity-revalidated flow that never deletes the PDF.
- **Unregistered** includes a direct **Register all** action that reuses the canonical existing-PDF registration flow.
- **Missing** intentionally remains read-only in the register; maintenance continues through the separate missing-document review flow.

## Community Plugin review cleanup

The 0.1.227 candidate also addresses findings from the Community scanner used on 0.1.226:

- the manifest description no longer contains the redundant word “Obsidian”;
- generated Email/Archive runtime bundles use syntax/whitespace minification without identifier minification, reducing `main.js` below the 5 MB Community/Sync target;
- `npm run check:community` prevents regression of the manifest, runtime-size and CSS review issues;
- active CSS no longer uses the flagged `!important`, `:has()` or `text-decoration-style` patterns;
- the Community release workflow rebuilds/verifies the frozen archive and creates GitHub artifact attestations for `main.js`, `manifest.json` and `styles.css`;
- README documents filesystem access, vault enumeration, clipboard use and the bundled dynamic-code dependency.

Vault enumeration and clipboard access remain intentional product behavior. The scanner's dynamic-code recommendation is traced to the bundled `source-map-js` dependency via `sanitize-html -> postcss -> source-map-js`; the dependency audit currently reports no known vulnerable dependencies.

## Identity and lifecycle contract

Ordinary PDF identity remains based on permanent `filemeta_id` UUID plus trusted Obsidian rename/move continuity.

The ordinary PDF lifecycle remains deliberately limited to:

- `active`;
- `missing`.

0.1.227 does not reintroduce ordinary-PDF SHA recovery, manual relink or the experimental `trashed` state.

## Practical verification

The 0.1.227 development line has been practically verified for:

- DocumentInfo top/bottom actions;
- Bokmål → English → Bokmål localized factory defaults with user customizations preserved;
- Settings/example-package cleanup;
- PDF-first Document Register and persistent **Velg Kolonner**;
- quick status filters and invalid-record diagnostics;
- selectable/copyable register text;
- duplicate-record comparison and guarded **Delete metadata**;
- final **Unregistered → Register all** closure flow.

Final release-candidate verification and the mandatory Community Review branch / preview scan are performed against the exact versioned candidate before merge/release.
