# PDFium Gate 0.1.227

## A clearer way to work with document collections

PDFium Gate 0.1.227 focuses on making document-heavy work easier to understand, faster to navigate, and safer to maintain.

### A more useful PDF Document register

The document register is now PDF-first and easier to tailor to the job at hand:

- choose which metadata columns to show;
- switch quickly between **Active**, **Missing**, **Errors**, **Unregistered**, and **All**;
- register previously unregistered PDFs in bulk with **Register all**;
- select and copy paths, UUIDs, diagnostics, and other technical values when investigating a problem;
- see duplicate metadata records grouped by the PDF they refer to;
- compare duplicate records and remove the wrong metadata record through a guarded flow that revalidates identity before deletion.

Deleting duplicate metadata through this maintenance flow never deletes the PDF itself.

### Better metadata editing

**Document information** now exposes Edit/Save/Cancel actions at both the top and bottom of the panel, making longer metadata forms easier to work with.

Factory metadata and category labels follow the selected interface language, while stable UUIDs, properties, machine values, and user-customized labels remain unchanged. This keeps the interface multilingual without rewriting user-owned data.

### Cleaner settings and examples

Settings are reorganized into compact, collapsible groups. The production PDF Document register is also more clearly separated from the optional synthetic/native Bases examples, making it easier to understand which views contain real document records.

### Safer handling of missing and unregistered documents

**Missing** documents remain deliberately read-only in the register. PDFium Gate does not silently relink a missing metadata record to another PDF.

**Unregistered** documents now have one clear bulk action: **Register all**. This reuses the normal PDF registration flow and creates ordinary metadata records with fresh identities.

## Community Plugin review cleanup

The 0.1.227 candidate also addresses findings from the Community scanner used on 0.1.226:

- the manifest description no longer contains the redundant word “Obsidian”;
- generated Email/Archive runtime bundles use syntax/whitespace minification without identifier minification, reducing `main.js` below the 5 MB Community/Sync target;
- `npm run check:community` prevents regression of the manifest, runtime-size and CSS review issues;
- active CSS no longer uses the flagged `!important`, `:has()` or `text-decoration-style` patterns;
- the Community release workflow rebuilds/verifies the frozen archive and creates GitHub artifact attestations for `main.js`, `manifest.json` and `styles.css`;
- README documents filesystem access, vault enumeration, clipboard use and the bundled dynamic-code dependency.

Vault enumeration and clipboard access remain intentional product behavior. The scanner's dynamic-code recommendation is traced to the bundled `source-map-js` dependency via `sanitize-html -> postcss -> source-map-js`; the dependency audit currently reports no known vulnerable dependencies.

## Identity and lifecycle contract

Ordinary PDF identity remains based on permanent `filemeta_id` UUID plus trusted Obsidian rename/move continuity.

The ordinary PDF lifecycle remains deliberately limited to:

- `active`;
- `missing`.

0.1.227 does not reintroduce ordinary-PDF SHA recovery, manual relink or the experimental `trashed` state.
