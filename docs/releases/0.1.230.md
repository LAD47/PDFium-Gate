# 0.1.230 — Document Register cleanup

## Resulting behavior

The PDFium Gate Document Register keeps its schema-aware **Choose columns**
control, including empty and alternative status views. The unrelated native
Obsidian Properties chooser is hidden only for the current
`pdfium-document-register` instance. Other Bases views retain it.

The native control is in a sibling `.bases-header`, outside `.bases-view`.
Ownership is checked through the enclosing Bases `.view-content`. Local
observation reconciles delayed/replaced chrome and view switching; unload
disconnects observation, invalidates queued work and removes owned markers.
Ambiguous or unsupported DOM shapes leave the native control visible.

Temporary UI reporting, the copy button, its report generator, clipboard
handling and all 21 associated translation entries have been removed.
Permanent DOM/lifecycle and column-picker regressions remain in the check pipeline.

Example installation creates `PDF Dokumentregister.base` only at the Vault
root when missing. It no longer installs or restores a second real register in
the example folder. The duplicate repository example snapshot is removed;
the canonical root-register generator remains. Two pedagogical native Bases,
six synthetic records and the example README remain. Existing root registers,
historical copies, legacy Bases, PDFs and metadata are not automatically
overwritten, moved or deleted.

New register view names use the selected UI language. Existing user-owned Base
files and labels remain untouched. Stored visibility, sorting, filtering,
inline editing, permanent metadata identifiers and values are preserved.
