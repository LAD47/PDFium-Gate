# 0.1.226 — Community release cleanup and README review

This document records planned release-infrastructure and documentation work for the next development release after 0.1.225.

## Why this work is needed

PDFium Gate is now distributed to ordinary users through **Obsidian Community Plugins**. Earlier development used BRAT during an initial test phase, but BRAT is no longer part of the intended distribution model.

The repository still contains active release terminology and workflow names that refer to BRAT. Those references are now misleading and should be removed from the active release path.

This cleanup is planned for **0.1.226**. It is release/documentation infrastructure work and should not alter the frozen 0.1.225 archive or its published release.

## Release workflow cleanup

For 0.1.226:

- rename the active GitHub Actions workflow from **Publish BRAT release** to a Community-oriented name such as **Publish Community Plugin release**;
- rename the workflow file accordingly, for example:
  - from `.github/workflows/publish-brat-release.yml`
  - to `.github/workflows/publish-community-release.yml`;
- remove active BRAT terminology from workflow comments, step names, release notes and release procedure;
- retain the GitHub Release mechanism and the required release assets:
  - `main.js`
  - `manifest.json`
  - `styles.css`;
- document that these GitHub release assets are consumed by the Obsidian Community Plugins distribution/update flow;
- remove `--prerelease` from the normal Community release workflow unless a future, explicitly separate test-channel design requires it;
- keep the frozen `archive/<version>` branch model as immutable release evidence;
- update `RELEASE.md` and `docs/architecture/14-release-readiness.md` so the primary release path is:

```text
main
  -> Build generated runtime
  -> freeze archive/<version>
  -> GitHub Release
  -> Obsidian Community Plugins
```

- remove or rewrite the old “future Community directory” wording now that PDFium Gate is already distributed through Community Plugins;
- remove active references to BRAT as a required or normal release channel;
- commit `package-lock.json` and use `npm ci` in CI so generated runtime is reproducible from the same dependency tree;
- keep release publishing manual-only so changing or merging the workflow itself cannot publish before the matching frozen archive exists.

Historical documents may retain BRAT references when they describe what actually happened during earlier development. Active documentation and workflows should not present BRAT as part of the current release process.

## README.md review for Obsidian Community Plugins

Before publishing 0.1.226, perform a dedicated README review with ordinary Community Plugins users as the primary audience.

The README should be optimized for someone who finds PDFium Gate through Obsidian rather than through the development history.

Review at least the following:

- make the first screen explain clearly and briefly what PDFium Gate does and who it is for;
- keep the public product identity consistent: **PDFium Gate** / `pdfium-gate`;
- make **Obsidian Community Plugins** the only normal installation path described;
- explain updates as normal Obsidian Community Plugins updates;
- remove BRAT terminology from active installation/release guidance;
- clearly state desktop-only support and the minimum supported Obsidian version;
- keep the backup warning prominent but concise and practical;
- distinguish current working features from experimental/future ideas;
- make Email Import, Archive Import, DocumentInfo, PDF annotations and metadata/document-register features easy to discover;
- explain important storage/data-ownership principles without overwhelming a new user;
- keep the README useful to end users first, with development/architecture links later;
- ensure wording matches the actual state of 0.1.226 and does not describe Community distribution as a future plan;
- review the public `manifest.json` author metadata and replace the development placeholder `OpenAI / test build` with the intended public author/maintainer metadata;
- review whether screenshots or a compact visual overview would materially improve the Community Plugins listing/readme experience;
- ensure issue-reporting guidance is simple and tells users which version, OS and Obsidian version to include.

## 0.1.225 historical integrity

Do not rewrite the frozen 0.1.225 release evidence merely to remove BRAT terminology.

Specifically:

- do not move or repoint `archive/0.1.225`;
- do not replace the published 0.1.225 assets;
- do not rewrite the historical 0.1.225 GitHub Release merely because it was published with the old workflow name;
- treat the existing 0.1.225 release as historical evidence of the exact release process used at that time.

Documentation on `main` may clarify that BRAT terminology in older material is historical.

## Definition of done for this cleanup

The cleanup is complete when:

1. no active GitHub Actions workflow is named or described as a BRAT publisher;
2. `RELEASE.md` describes the real Community Plugins release path;
3. the normal release workflow creates the correct GitHub Release and required plugin assets without BRAT terminology;
4. the normal Community release is not marked GitHub Pre-release unless that status is explicitly intended;
5. `README.md` is reviewed and optimized for ordinary Obsidian Community Plugins users;
6. active installation/update documentation points to Obsidian Community Plugins;
7. historical 0.1.225 release evidence remains unchanged;
8. the full repository verification pipeline remains green after the cleanup;
9. npm dependencies are locked and CI uses `npm ci` for reproducible runtime generation;
10. Community release publishing is manual-only and requires the matching frozen archive.
